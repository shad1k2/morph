# MORPH

**Одно касание — любой интерфейс.**

MORPH — приложение для прямой передачи файлов между Android-устройствами, чей
интерфейс меняется под оболочку устройства: Material 3 на Pixel, Liquid Glass на
HyperOS, точечный NDot + Geist на Nothing OS и так далее.

Транспорт гибридный: **касание NFC** создаёт доверенную сессию, **BLE** несёт
обнаружение, близость и управляющие сообщения, а **Wi‑Fi Aware / Direct**
передаёт сам файл. Проволочный протокол свой — [`DROP/1`](docs/PROTOCOL.md).
Архитектура и выбор языков — в [`ARCHITECTURE.md`](docs/ARCHITECTURE.md),
дизайн-пакеты оболочек — в [`THEMES.md`](docs/THEMES.md).

> Статус: **v1.1.0** — `morph-core` реализован и покрыт регрессионными тестами;
> `morph-app` по касанию NFC поднимает сессию **Bluetooth + Wi-Fi Direct**, и
> любой из телефонов может стать отправителем из общей карточки Receive. Файлы
> сохраняются в `Downloads/MORPH` после X25519 + AES-256-GCM и показываются в
> системном оверлее.

## Установка

Скачайте подписанный APK из
[Releases](https://github.com/shad1k2/morph/releases/latest). Нужен Android 10
(API 29) или новее; для передачи касанием NFC требуется NFC-модуль.

## Сборка

```bash
# Нужны JDK 17 и Android SDK 35.
./gradlew :core:check          # юнит-тесты
./gradlew :app:assembleDebug   # debug APK
./gradlew :app:assembleRelease # подписанный release (см. ниже)
```

Release подписывается из `keystore.properties` или переменных окружения
(`MORPH_KEYSTORE`, `MORPH_KEYSTORE_PASSWORD`, `MORPH_KEY_ALIAS`,
`MORPH_KEY_PASSWORD`). Файл добавлен в `.gitignore`. CI запускается на каждый
push/PR, а пуш тега `v*` публикует подписанный APK с SHA-256 через GitHub
Actions.

## Принцип дизайна

Оболочка — не просто набор тем, а часть протокола. Устройства обмениваются
`shell_id` в capabilities, поэтому обе стороны рисуют экран подтверждения на
визуальном языке получателя.

| Оболочка | Язык дизайна |
|---|---|
| Pixel / AOSP | Material 3 Expressive, dynamic color |
| Xiaomi HyperOS | Liquid Glass: полупрозрачность, blur, блики |
| Samsung One UI | Мягкие слоистые пилюли и карточки |
| OPPO ColorOS | Естественный свет, текстуры, слоистые тени |
| vivo OriginOS | Матовые градиенты, плавное движение, vivo Sans |
| Huawei HarmonyOS | «Звёздный» серый, слоистые полупрозрачные поверхности |
| Nothing OS | NDot, Geist, `#1B1B1D` + `#D71921` |

`app/` — Android-клиент. Определяет оболочку и перекрашивает весь поток: заголовок
и живой радар на главном экране, найденные по mDNS телефоны, настоящий SAF-выбор
файлов, AirDrop-карточка с приёмом/отклонением и реальным прогрессом, настройки с
превью стилей, статусом движка, loopback-самотестом и данными протокола. У каждого
пака свой силуэт и брендовый овал, а не только акцент: светлые One UI/ColorOS,
стекло HyperOS/OriginOS, слоистый HarmonyOS, плоские Nothing OS и Pixel.

## Тайл в шторке

Добавь **MORPH drop** в шторку: свайп вниз дважды → карандаш → перетащи тайл.
Тап сворачивает шторку и показывает карточку поверх текущего приложения. Нужно
разрешение «Поверх других приложений» — выдаётся один раз из баннера на главном
или в настройках → Pop-up over apps.

Оверлей — настоящее окно `TYPE_APPLICATION_OVERLAY` с Compose, а не
полноэкранная активити, поэтому приложение под ним продолжает работать.

## Транспорт

В v1.1.0 работает полный сценарий касания. Приложите телефоны: MORPH эмулирует
NDEF-тег Type 4 через HCE (AID `D2760000850101`) с записью `MORPH/1`, моделью,
IP, TCP-портом, shell_id и идентификатором сессии. Затем оба телефона:

- поднимают **Bluetooth LE**-канал управления — владелец тега рекламирует GATT-
  сервис с UUID, производным от id NFC-сессии, а читатель сканирует и
  подключается;
- запускают **Wi-Fi Direct** с DNS-SD по тому же id сессии: group owner держит
  TCP-сервер, а P2P-клиент подключается к нему;
- показывают одинаковую карточку **Receive** с кнопкой **SEND FILES**.

Кто первым нажал SEND FILES — тот отправитель; второй телефон автоматически
переходит в приём. Одновременное нажатие разрешается детерминированно (побеждает
читатель NFC). Если Bluetooth/Wi-Fi Direct недоступны или нет разрешений,
сессия откатывается на прямой TCP в локальной сети, но выбор роли остаётся тем
же.

Сам путь передачи данных:

```
NFC tap            -> id сессии + IP/порт/shell         (HCE Type-4 NDEF)
BLE GATT           -> присутствие + заявка роли          (UUID сессии)
Wi-Fi Direct       -> DNS-SD + P2P-группа                (клиент звонит owner)
MORPH/1 HELLO      -> id сессии, id устройства, роль     (строчный протокол)
SEND / ROLE R      -> кто отправляет
FILE               -> файл выбран, затем стартует DROP/1
mDNS (_morph._tcp) -> список устройств в LAN (fallback)  (NSD на Android)
TCP :44771         -> сессия DropLink
HELLO              -> публичные ключи X25519
CAPS               -> shell_id, флаги, MTU
OFFER / ACCEPT     -> манифест с SHA-256 каждого файла
CHUNK*             -> кадры AES-256-GCM, payload 32 КиБ
DONE / ACK         -> хеш манифеста проверен, файл финализирован
```

Принятые файлы попадают в `Downloads/MORPH` через MediaStore, поэтому переживают
перезагрузку и видны в «Файлах». Карточка показывает реальные байты и проценты, а
не таймер.

Старый путь mDNS + прямой TCP остаётся запасным, если BLE/Wi-Fi Direct
недоступны, и используется для ручного выбора устройства из списка.

### Самотест

Настройки → Transmission → **SELF-TEST** прогоняет полноценную зашифрованную
передачу 512 КБ по loopback-TCP на одном телефоне. Если написано `Loopback OK`,
значит работают фрейминг, обмен ключами, AEAD и сборка файла.

**E2E RECEIVE TEST** идёт дальше: объявляет `_morph._tcp`, находит этот же
телефон через mDNS и отправляет 256 КБ собственному приёмнику через TCP, X25519 +
AES-GCM и MediaStore. В конце показывает имя сохранённого файла, который реально
появляется в `Downloads/MORPH`. Между двумя телефонами используется тот же путь.
